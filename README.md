# BitBlockerInstaller (BitTorrent Blocker)

**BitBlockerInstaller** устанавливает DPI-детектор на базе **nDPId / nDPI**, который распознаёт BitTorrent-трафик и **точечно блокирует обнаруженные потоки**, не затрагивая остальной трафик сервера. Дополнительно скрипт блокирует известные DHT bootstrap-узлы и автоматически обновляет их IP-адреса.

Для захвата пакетов используется `libpcap`, для блокировки — `ipset` и `iptables`. Сборка специального модуля ядра не требуется.

> **Важно:** блокировка потока выполняется после его распознавания nDPI. Определение BitTorrent только по номеру порта не используется.

## Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/sngvy/BitBlockerInstaller/refs/heads/main/BitBlockerInstaller.sh)
```

Во время установки можно выбрать способ сохранения правил (**iptables + iptables-persistent** или **UFW**) и при необходимости настроить BPF-фильтр захвата трафика.

Если рабочий бинарник `nDPId` уже установлен, его повторная сборка пропускается. В противном случае сборка выполняется с индикатором прогресса; подробный лог выводится при ошибке.

При необходимости можно зафиксировать конкретный тег или коммит nDPId при запуске локального установщика:

```bash
NDPID_REF="<тег или коммит>" bash BitBlockerInstaller.sh
```

## Как работает блокировка

### 1. Захват и анализ трафика

- **Захват:** `nDPId` получает пакеты с сетевого интерфейса через `libpcap` в userspace.
- **BPF-фильтр:** при установке можно ограничить захват выбранными портами и диапазонами либо исключить указанные порты.
- **Проверка портов:** допускается не более **15 позиций**, причём диапазон учитывается как две позиции.
- **Распознавание:** `nDPI` анализирует потоки, а `nDPId` передаёт JSON-события слушателю BitBlocker через UNIX-сокет с правами `600`.

### 2. Решение о блокировке

BitBlocker реагирует на события `detected` и `detection-update`, **только если протокол определён как BitTorrent**.

Для обнаруженного потока слушатель добавляет его концы (источник и приёмник) в два набора `ipset` типа `hash:ip,port`.

| Параметр | Поведение |
| --- | --- |
| Срок действия записи | **24 часа** |
| Повторные события одного потока | Не обрабатываются в течение **10 минут** |
| Последующие события | Продлевают TTL записи |
| Ошибка добавления в `ipset` | Записывается в лог с меткой `[ERROR]` |

Таким образом, наборы содержат адреса и порты конкретных обнаруженных потоков, а не бесконечно растущий список отдельных правил файрвола.

### 3. Фильтрация пакетов

BitBlocker создаёт цепочку `BITBLOCKER` в таблице **`raw`** и подключает её к `PREROUTING` и `OUTPUT`, то есть блокировка выполняется **до conntrack**.

В цепочке используются три правила:

1. Блокировка обнаруженного BitTorrent-потока.
2. Блокировка ответного направления этого потока.
3. Блокировка известных DHT bootstrap-узлов.

Количество правил остаётся постоянным. При обновлении они пересобираются одной транзакцией через `iptables-restore --noflush`, без накопления дубликатов.

## Блокировка DHT bootstrap-узлов

Дополнительно BitBlocker блокирует известные адреса DHT bootstrap-серверов, включая `router.bittorrent.com`.

- Доменные имена разрешаются в IP-адреса и загружаются в наборы `bitblocker_dht4` и `bitblocker_dht6`.
- Частные IP-адреса исключаются.
- Обновление выполняется **каждые 30 минут** через systemd-таймер.
- Новые наборы подготавливаются отдельно и подменяются атомарно через `ipset swap`.
- При ошибке DNS или резком сокращении полученного списка сохраняется предыдущий набор.

## Интеграция с файрволом

При установке доступно два варианта:

| Режим | Сохранение правил |
| --- | --- |
| **iptables + iptables-persistent** | Правила записываются в `rules.v4` и `rules.v6` |
| **UFW** | Правила восстанавливаются слушателем и таймером |

**В обоих режимах блокировка работает напрямую в таблице `raw`.** Выбор UFW или iptables влияет на способ сохранения и восстановления правил, но не переносит блокировку в цепочки UFW.

### Восстановление после перезагрузки

Служба `bitblocker-ipset` создаёт необходимые наборы и восстанавливает DHT-список **до загрузки файрвола**. Это важно: правила с `--match-set` не могут быть восстановлены, пока соответствующие наборы `ipset` ещё не существуют.

## Службы и файлы

| Компонент | Назначение |
| --- | --- |
| `bitblocker-ipset` | Подготовка наборов `ipset` при запуске системы |
| `bitblocker-ndpid` | DPI-детектор nDPId |
| `bitblocker-listener` | Обработка событий и добавление обнаруженных потоков в `ipset` |
| `bitblocker-dht-block` | Таймер обновления DHT-адресов |
| `/etc/bitblocker/bitblocker.conf` | Конфигурация BitBlocker |
| `/var/log/bitblocker.log` | Основной лог работы |

Службы `bitblocker-listener` и `bitblocker-ndpid` настроены с `Restart=always`. Лог ротируется ежедневно, хранятся записи за **7 дней**.

## Обновление и миграция

При повторном запуске поверх старой версии установщик:

1. Создаёт резервную копию изменяемых настроек и правил.
2. Переносит записи обнаруженных потоков в новые наборы `ipset`.
3. Удаляет устаревшие наборы `BITBLOCKER-*` и прежнюю DHT-цепочку в таблице `filter`.
4. Удаляет старые правила UFW с меткой `BitBlocker-DHT` и записи в `/etc/iptables/ipsets`.
5. Проверяет результат миграции.

**Резервные копии удаляются только после успешной проверки.** Если проверка не пройдена или список DHT не удалось загрузить, старые DHT-правила и резервные копии сохраняются для ручного отката.

## Удаление

В меню установщика предусмотрен пункт **«Удалить»**. Он удаляет:

- systemd-службы BitBlocker;
- цепочку `BITBLOCKER` и соответствующие наборы `ipset`;
- конфигурацию BitBlocker;
- сохранённые правила в `rules.v4` и `rules.v6`, относящиеся к BitBlocker.

Это предотвращает появление после перезагрузки правил, ссылающихся на уже удалённые наборы.

## Важные особенности

- **Блокируются распознанные BitTorrent-потоки**, а не любые соединения на «торрент-портах».
- **BPF-фильтр ограничивает область анализа:** трафик вне выбранных условий не поступает на распознавание nDPId.
- **DHT-список дополняет DPI:** известные bootstrap-узлы блокируются отдельно от обнаруженных потоков.
- **Выбор UFW не меняет расположение правил:** они по-прежнему работают в таблице `raw` до conntrack.
